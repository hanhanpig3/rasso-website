FIG.06 — 架构优势对比

为什么需要现代沙箱？对比传统插件启动器与 RASSO 在进程隔离、通信安全与隐私边界上的本质区别。

对比维度 传统方案 (Legacy Launchers) RASSO 架构 (Next-Gen)
运行容器 主进程混跑 / 开启 NodeIntegration / 普通 Webview 易内存泄露 独立 WebContentsView 强隔离 + 硬件加速独立沙箱进程
通信安全 开放全双工 IPC / 插件可直接调用任意 Node.js 原生底层模块 严格 contextBridge 管道白名单 + 最小权限按需声明机制
隐私与追踪 商业闭源 / 强制绑定账号 / 上传用户输入与击键遥测数据 100% 本地开源 · MIT 协议 · 零网络遥测 · 零数据回传
常驻开销 常驻后台占用 100MB+ 内存，冷启动有明显卡顿与延迟 42ms 瞬时冷启动 · 28MB RSS 后台轻量驻留
FIG.07 — 插件开发指南

无需学习复杂的私有 DSL。基于标准 Web 规范与现代前端生态，只需 3 步即可构建原生级启动器插件。

01 / 声明清单 plugin.json

配置插件名称、入口主页面、唤起关键字（cmds）与匹配交互模式。

{
  "name": "my-tool",
  "pluginName": "快捷百宝箱",
  "main": "index.html",
  "features": [{
    "code": "box",
    "cmds": ["tool", "工具"]
  }]
}
02 / 编写前端 UI Vue / React / HTML

自由选用熟悉的前端技术栈，无需依赖定制编译器，支持任意样式库。

<div id="root">
  <input class="input"
    placeholder="输入参数..." />
  <button onclick="convert()">
    执行转换
  </button>
</div>
03 / 调用沙箱 API window.rubick

通过 contextBridge 安全通道写入剪贴板、发起截图或与主应用协同。

// 安全写入剪贴板并退出
window.rubick.copyText(result);
window.rubick.showToast("已复制");
window.rubick.outPlugin();
